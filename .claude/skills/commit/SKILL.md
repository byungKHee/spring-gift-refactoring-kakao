현재까지의 변경사항을 분석하여 아래 AngularJS 커밋 컨벤션에 맞는 **한글** 커밋 메시지를 생성하고, 커밋을 수행한다.

## 절차

1. `git status`를 실행하여 현재 변경사항(스테이징됨 + 스테이징 안 됨 + 새 파일)을 확인한다.
2. 변경사항이 없으면 사용자에게 알리고 중단한다.
3. 스테이징되지 않은 변경사항이 있으면 변경된 파일을 개별적으로 `git add <파일>` 한다. (비밀 정보가 포함된 파일(.env, credentials 등)은 제외하고 사용자에게 경고한다.)
4. `git diff --staged`를 실행하여 스테이징된 전체 변경사항을 확인한다.
5. 변경사항을 분석하여 아래 형식 규칙에 따른 커밋 메시지를 생성한다.
6. 생성된 커밋 메시지를 사용자에게 보여주고, 확인을 받은 후 커밋한다.
7. 커밋 메시지는 반드시 HEREDOC 형식으로 전달한다:
   ```bash
   git commit -m "$(cat <<'EOF'
   커밋 메시지 내용

   Co-Authored-By: Claude Opus 4.6 <noreply@anthropic.com>
   EOF
   )"
   ```
8. 커밋 후 `git status`로 결과를 확인한다.

## 커밋 메시지 형식

```
<type>(<scope>): <한글 subject>
<빈 줄>
<한글 body>
<빈 줄>
<footer>
```

- 모든 줄은 100자를 초과할 수 없다.
- body와 footer는 선택사항이다. 의미 있는 맥락을 추가할 때만 포함한다.

### 제목 줄

#### 허용되는 `<type>`
- **feat**: 새로운 기능
- **fix**: 버그 수정
- **docs**: 문서 변경만
- **style**: 코드 포맷팅, 세미콜론 누락 등 (로직 변경 없음)
- **refactor**: 기능 추가나 버그 수정 없이 코드 구조 변경
- **test**: 테스트 추가 또는 수정
- **chore**: 유지보수 작업 (빌드, CI, 의존성 등)

#### `<scope>`
- 변경이 일어난 위치를 나타낸다 (예: 모듈, 클래스, 패키지명).
- 소문자 영어를 사용한다.
- 예시: `product`, `order`, `auth`, `wishlist`, `build`

#### `<subject>` 텍스트
- **한글**로 작성한다.
- 명령형으로 작성한다: "변경했음"이 아닌 "변경"
- 첫 글자를 대문자로 쓰지 않는다
- 끝에 마침표(.)를 붙이지 않는다

### 메시지 본문 (선택사항)
- **한글**로 작성한다.
- 변경 동기와 이전 동작과의 차이를 포함한다.
- 제목 줄만으로 변경사항을 설명하기 충분하지 않을 때만 포함한다.

### 메시지 푸터 (선택사항)

#### 호환성을 깨뜨리는 변경
`BREAKING CHANGE:` 접두사를 붙이고, 변경 내용, 사유, 마이그레이션 방법을 한글로 기술한다.

#### 이슈 참조
`Closes #<이슈번호>` 형식을 사용한다 (예: `Closes #234` 또는 `Closes #123, #245`).

## 규칙

- type과 scope는 **영어**, subject와 body는 **한글**로 작성한다.
- 메시지는 간결하고 의미 있게 작성한다.
- 변경이 단순하고 제목만으로 충분히 설명되면 body나 footer를 포함하지 않는다.
- 실제 diff 내용에 따라 가장 정확한 `<type>`을 선택한다.
- 변경된 코드베이스 영역을 가장 잘 나타내는 `<scope>`를 선택한다.

## 예시

```
feat(auth): 카카오 로그인 기능 추가

카카오 OAuth2 인증 플로우를 구현:
- 인가 코드 발급 요청 엔드포인트 추가
- 액세스 토큰 교환 로직 구현
- 사용자 정보 조회 후 자동 회원가입 처리
```

```
fix(product): 상품 가격이 음수일 때 검증 오류 수정

Closes #392
```

```
refactor(service): TDD 기반 서비스 계층 추출
```

```
docs(guide): API 문서 오타 수정
```

```
feat(wishlist): 위시리스트 페이지네이션 지원

기존에는 전체 목록을 한 번에 반환했으나,
대량 데이터 처리를 위해 페이지네이션을 적용

BREAKING CHANGE: GET /api/wishlists 응답 형식이 배열에서 Page 객체로 변경됨

이전: [{ id: 1, ... }]
이후: { content: [{ id: 1, ... }], page: 0, size: 10, totalElements: 100 }
```
